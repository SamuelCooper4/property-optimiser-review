Research date: 2 November 2026. This is design research, not evidence of financial-model capability or user acceptance. The R4 owner brief supersedes the older scoped instruction to stop before R4 for this isolated experiment.

The OWID chart's actual 850 × 600 PNG was downloaded to temporary storage and visually inspected: endpoint labels, fine horizontal guides, unsmoothed reversals and the source footer are visible. Retained references and applied lessons

1. Calculator.net — UK Mortgage Calculator

Actual tool. Rendered desktop/mobile results, chart and schedule inspected; term changed and Calculate operated.

- Question / relationship: What does this loan cost monthly, and how does each payment change debt? Inputs lead to payment totals and a dated principal/interest/balance schedule.
- Interaction: Explicit Calculate and optional cost fields; a useful boundary between edits and results.
- Appeal / mobile: Green repayment headings are prominent; the 390px layout stacks Calculate above results. The tiny amortization plot mixes remaining balance with cumulative payment/interest lines.
- Adapt / avoid: Keep Calculate and an expandable exact-value schedule. Separate debt from cumulative costs; avoid ambiguous “Payment” labeling. Do not copy assumptions, cost taxonomy or formulas; do not let a long table dominate the workspace.

2. Our World in Data — Life expectancy

Chart and provenance, inspected static chart.

- Question / relationship: How do series change over the same dates? Shared axes reveal absolute levels and actual falls.
- Interaction: The interactive chart is the intended exploration entry point; only its page and static export were inspected here, so no control behavior is asserted.
- Appeal / mobile: Direct endpoint names and subdued guides reduce legend hunting. Several nearby labels need more vertical room at narrow widths.
- Adapt / avoid: Label selected/pinned trajectory endpoints directly; preserve visible losses. Limit simultaneous paths and offer expanded charts rather than shrinking the labels. Keep source/model details adjacent.

3. The Pudding — Film Dialogue

Actual interactive article. Rendered desktop/mobile article, grouped horizontal bars and detailed explorer inspected. Filters were not operated.

- Question / relationship: Does an aggregate result hold within a selected subset? The article moves from a familiar subset to broader comparisons and individual films.
- Interaction: Genre/year filters and film search make a large collection approachable.
- Appeal / mobile: Three grouped bar columns make the familiar opening subset readable. On resize to 390px, the first comparison overflows horizontally, while later age panels stack; the captured full-page width is 965px. Do not copy that overflow behavior.
- Adapt / avoid: Organize the library by questions, then expose detailed tiles; use one coherent default example. Avoid transferring population percentages or this article's subject-specific encoding to financial uncertainty.

4. Bank of England — February 2026 report, Chart 3.5

Report, PDF, printed page 65. Chart caption, scenario descriptions and limitations inspected; screenshot retrieval did not expose an image to visual inspection.

- Question / relationship: How does a changed assumption alter a path? Paired scenario panels compare conditional paths against a central case.
- Interaction: Static reference; our adaptation adds selecting a named scenario.
- Appeal / mobile: Consistent panels make comparison disciplined; stack them vertically on mobile with identical axes.
- Adapt / avoid: Separate named adverse paths from the baseline and explain what changed. Do not import Bank forecasts, policy prescriptions, confidence intervals or probabilities into this prototype.

5. Observable Plot — pointer and crosshair examples

Interaction examples. Actual Olympian scatterplot hovered; named tooltip and mobile-sized chart inspected alongside documentation.

- Question / relationship: Which exact values belong to the mark being inspected? Nearest-point emphasis connects position with numbers.
- Interaction: Pointer tips and crosshairs; the documented axis-edge readout avoids covering marks.
- Appeal / mobile: The tooltip reveals a name and exact measures but covers points. At 390px the plot fits, yet its proportionally shrunk axis labels are tiny. Pointer-only behavior is insufficient on touch or keyboard.
- Adapt / avoid: Keep a persistent selected-plan readout below the chart and a separate transient hover preview. Commit via tap/click or explicit controls; never move the calculated-best marker merely because the pointer moves.

6. Observable Plot — volcano contour example

Contour examples and method. Actual line and filled volcano plots inspected at desktop and mobile widths, alongside their 87 × 61 grid specifications.

- Question / relationship: Where do combinations share a similar value? Isolines connect equal values in a two-dimensional grid.
- Interaction: This reference is a static chart specification; our map selection would link a cell to plan details.
- Appeal / mobile: Unfilled isolines reveal shape without 3D occlusion; the filled example's rainbow palette dominates. At 390px the chart fits but ticks become tiny. Use a restrained sequential palette and explicit mobile typography.
- Adapt / avoid: Compare evaluated-cell heatmaps with discrete near-best region outlines. Do not interpolate across infeasible cells or smooth away LTV cliffs; a contour-like view must disclose its discrete sampling.

7. Apache ECharts — accessible chart examples

ARIA and decal examples. Pie-chart description and decal configuration examples inspected in documentation.

- Question / relationship: Can series remain distinguishable without color? Patterns supplement color and descriptions expose meaning.
- Interaction: This source documents descriptions, not a complete keyboard-selection experience.
- Appeal / mobile: Hatching is consistent with our existing interest graphic; too many patterns become noisy at small sizes.
- Adapt / avoid: Use shape/line style for best, inspected and pinned identity; hatch excluded combinations. Supply concise summaries and selected numerical details. Do not assume enabling ARIA makes an interactive chart accessible.

8. W3C WAI — complex-image examples

Examples and structured descriptions. Long-description approaches and chart-equivalent content inspected.

- Question / relationship: What essential information is lost when the graphic cannot be seen? A short identification links to a longer structured explanation.
- Interaction: Adjacent links/disclosure can reveal the detailed equivalent without overwhelming the chart.
- Appeal / mobile: A concise chart summary works in a narrow column; large tables need controlled expansion.
- Adapt / avoid: Give each tile a question, concise interpretation and exact data access. Use real buttons/sliders for selection. Avoid a single enormous accessible label or a chart that only works on hover.

Stack decision

Inspected design/r3-v12/package.json, src/Comparison.jsx, src/StoryScene.jsx, src/DepositControl.jsx and styling. The baseline uses React 19.3.1, Vite 8.3.4, GSAP 3.13.0, Pyodide 0.29.3, authored SVG, HTML controls and reduced-motion handling; no chart package. This recommendation concerns rendering only. Financial outputs remain in the shared Python/provider contract.

Choice Interaction and transitions Accessibility / responsive behavior Performance / maintenance / licensing

Reuse React SVG + existing GSAP Shared React selection can connect charts and familiar illustrations directly. Animate emphasis and object continuity, not financial recomputation. Native HTML controls, visible focus, SVG descriptions and numerical equivalents remain explicit work. Responsive viewBoxes still need mobile label/layout changes. No new chart dependency. Appropriate provisional choice for modest sampled grids and monthly paths; mount expensive views only on demand. Author shared chart primitives to avoid repeated geometry/state code. Existing dependency terms remain applicable.
Apache ECharts Events/actions and data transitions provide useful building blocks. Shared plan state and hover/commit distinctions still need an adapter. ARIA/decal support is opt-in; keyboard and numerical-equivalent behavior still require design. Responsive containers need resize handling. Canvas/SVG guidance supports choosing by workload, not assuming a universal winner. Good fallback if measured dense-map rendering becomes costly. Apache 2.0 license; preserve applicable notices if adopted. No dependency added for this research.
Observable Plot Concise marks, facets, contours and pointer inspection. Current docs state direct selection is under development, pan/zoom and declarative animation planned, and ordinary updates replace the plot. That adds integration work for this connected workspace. ARIA options exist; touch/keyboard controls and persistent selection remain application work. Attractive for static analytical alternatives, less compelling as the primary selection surface here. ISC license; retain copyright/permission notice if adopted. No code or assets copied.

Provisional decision: reuse the current SVG/React stack with shared chart primitives and one selection contract. This is an architectural judgment, not a benchmark result. Reconsider ECharts only after a concrete performance or maintenance problem; do not add a second renderer merely for visual variety.
